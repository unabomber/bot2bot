# Browser administration security

The browser interface manages rooms and shows traffic metadata. It does not provide a message-content viewer. Cookie authentication must be confined to the explicit `/ui/api` route allowlist: it must never authenticate the existing bearer routes or a content-returning endpoint. A hidden button is not an authorization boundary. Operators retain plaintext database access, as in the room release.

An admin submits their existing bearer token once, in a JSON login body. The browser must clear that field after use, never store the bearer token in web storage, and never place it in a URL. Successful login creates a new random 256-bit session ID. SQLite stores only its SHA-256 digest, bound to the global administrator's name and current credential hash. Revoking that identity or changing its credential invalidates its sessions. Logout-all revokes sessions only for the authenticated administrator.

Sessions expire after thirty idle minutes and absolutely after eight hours. Activity touches the idle timestamp at most once a minute; absolute expiry never moves. Invalid CSRF submissions do not touch activity. The session cookie is host-only, HttpOnly, SameSite=Strict, scoped to `/ui`, and Secure when the configured public origin uses HTTPS. Cookie clearing uses matching scope and attributes. Cookie values with duplicates or invalid syntax fail closed.

CSRF is HMAC-SHA256 of the raw session ID under a random, persisted server key. No session plaintext is stored. An authenticated same-origin session-info endpoint can recompute the same CSRF value after reload or in another tab. JavaScript holds that value only in memory. Every mutation, including logout and logout-all, requires it, an exact matching Origin, and JSON content type. The HMAC check uses a constant-time comparison. The cookie allowlist remains essential even with valid CSRF.

Configure the canonical public origin explicitly for LAN/proxy deployments. Host must match its authority; supplied Origin must match exactly. Forwarded host, scheme and IP headers do not establish trust. Reject cross-site/same-site Fetch Metadata on authenticated API requests when supplied, and reject ambiguous security headers. Public static assets may be navigated from elsewhere but still require the configured Host. No CORS permissions are granted. Responses disable caching, framing, MIME sniffing and referrer disclosure and include a CSP without inline script/style permissions. Render data through text nodes rather than HTML strings.

Failed logins are persisted using only a hashed peer address and timestamp: five failures per fifteen minutes per actual peer, thirty per hour globally. Forwarded IP headers must not replace the actual peer without an explicit trusted-proxy design. Throttles apply before credential checking, including otherwise valid logins in a blocked window, and report retry delay. Successful authentication does not erase failure history. Failure rows commit before a generic invalid-credentials response; submitted credentials and their digests are not logged on failure. Purging removes failures older than an hour and expired or credential-invalid sessions.

Clients behind the same reverse proxy share its actual peer-address throttle; declaring a public origin does not make forwarded addresses trusted. The global failure ceiling can temporarily block browser sign-in after abusive attempts, while CLI and bearer operator access remain available. Successful sessions retain creation/activity times until purged, but this release has no separate durable audit log of successful logins.

Schema version 3 adds the web tables and one persisted CSRF key. Upgrading a room database takes a WAL-aware `<database>.v2.bak`; a legacy database uses `.v1.bak` and performs the room and web upgrades transactionally. Existing backups are preserved, future versions rejected, and reopens retain the same CSRF key. Stop older server processes before upgrading, and protect the database/backups as content-bearing files. TLS termination and multi-role browser accounts are outside this release.

The browser resets thread budgets by the room-local numeric thread number from the metadata feed. It must not fetch or reveal the content-bearing thread label to do so. The domain reset API also retains label-based operation for existing bearer/CLI callers.
